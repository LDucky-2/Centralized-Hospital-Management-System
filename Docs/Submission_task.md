You are required to prepare and submit a comprehensive Final Report documenting your project work (one report per team in Google Classroom). The report must cover the following sections:

1. Software Requirements Specification (SRS): Complete documentation of the project requirements. [Need to strictly follow the guideline provided earlier]

2. Software Design Specification (SDS): Detailed design documentation (UML Use case diagram, narratives of all the use cases, UML state diagram, DFD Level 0) of the proposed system.

- Installation and setup instructions.

- Sample source code with appropriate documentation comments.

7. UI Design: Include representative screenshots of your project's user interface and briefly explain the key screens and their functionalities.

8. Nielsen's Usability Heuristics: Identify the tools/plugins used to evaluate your UI against Nielsen's 10 Usability Heuristics. Explain how these tools assist in identifying usability issues and improving the overall UI design.

9. Code Review Tools and Findings: Describe the code review tool(s) used in your project. Include at least five examples of bugs, code smells, or other issues detected by the tool(s), along with relevant screenshots and brief explanations of the findings and corrective actions taken (where applicable).

10. Evidence of Usage of Git: Include sample screenshots (branches, commit, version history) demonstrating how you used Git

11. Unit Testing (Test Coverage and Quality): Include representative unit test cases with brief explanations of what each test verifies. Demonstrate the quality of your unit tests by showing how they cover normal cases, boundary conditions, invalid inputs, and exceptional situations.

12. Individual Team Member Contributions: Include a clear description of the contributions made by each team member throughout the project. Specify each member's responsibilities, assigned tasks, and actual contributions to the project development process. Contributions may include requirements analysis, SRS/SDS preparation, UI design, coding, testing, documentation etc.

Important: Ensure that every section is supported by appropriate explanations, examples, and screenshots wherever applicable. The report should reflect the actual tools, practices, and development activities followed by your team rather than simply providing theoretical descriptions.
